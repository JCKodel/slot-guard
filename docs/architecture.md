# Architecture

`hooks/register.js` keeps one state machine per agent turn, keyed by agent ID (a `/clear` changes the session ID mid-flight, never the agent). The first `turn.step` acquires one ticket in the global `agent` pool. Only `turn.step` waits for a grant: tools run on the ticket whether granted or queued. Rotation (cooperative multitasking): a step's acquire carries `rotate` when the agent has no step or tool in flight, a tool's start sends `op: rotate` under the same condition, and the heartbeat sends it for agents in a long tool with no step in flight. Excess grants yield between model calls immediately. Otherwise, the coordinator rotates a ticket granted for at least `quantum` seconds (config, default 60) only if another ticket is queued: in one transaction it becomes queued with rank 1 and a position after every ticket (`pos`), and `_promote` grants the next. Grants record `since`; queue order is rank, then `coalesce(pos, seq)`. A subagent claiming its parent's parked ticket sends `fresh`, restarting `since`. Every rotation decision runs under the agent's lock, the same lock a step's admission takes, so no step can start between the check and the rotation; rotation therefore never puts more agents in a model call than the limit (manual-mode forced admissions and explicit sprints are exceptions). A queued ticket of rank 1 waiting 300 s (`coalesce(waited, created)`) is raised to rank 0, so new subagents cannot starve prompts or rotated agents. `turn.complete` closes the state; release waits until outstanding ordinary work has unwound.

Each agent tracks busy operations (model streams and ordinary tools) and wait operations. `Agent`, legacy `Task`, blocking `TaskOutput`, `AskUserQuestion`, `ExitPlanMode`, and `Bash` commands that run `claude` are waits. A `tool.check` verdict of `ask` still unanswered after 15 s turns the admitted call into a wait, so a permission prompt does not hold a slot while the person is away. The delay matters in auto mode, where most calls are an `ask` answered by the classifier within seconds: yielding at once sent every agent to the back of FIFO on each tool call. In rare parallel timing (another tool of the same agent requeued ahead of it) the `tool.check` hook can exceed its budget waiting for the agent's lock; the engine's verdict stands and the state stays consistent. An agent with child waits and no busy operations releases its ticket. It obtains a new generation ticket before resuming inference or ordinary tool work, entering at the back of FIFO. If an ordinary tool is running alongside a child wait, the agent remains counted. State transitions are serialized within the mod; tool execution itself remains concurrent.

Subagents follow exactly the same admission path as main agents and release on their own `turn.complete`. A new turn for an agent whose previous turn never reported completion closes that turn instead of failing. No two-pool admission or parent-only reservation remains. A tool outside an admitted agent turn is denied, rather than silently bypassing admission. Both inference and tool hook error fallbacks refuse to call their next handler.

Each coordinator call runs the fixed argv `python3 guard.py client` with `cwd` set to the installed plugin root. JSON stdin carries only coordination identifiers. Python identifies the native Claude ancestor and uses SQLite WAL plus `flock` to serialize FIFO admission across processes. Owner birth identity protects against PID reuse. Unknown liveness retains reservations; confirmed dead owners are reaped on a subsequent call.

A released generation stays as a tombstone until its process dies or for one hour, preventing delayed acquires from reviving canceled work.

## Liveness inside a living process

Owner death alone cannot free a ticket the owner forgot, because the owner is the long-lived Claude process. Four mechanisms bound that:

1. **Retried release.** Release never throws; a failed release (an interrupted dispatch aborts its own calls, a lock timeout) is retried at the agent's next step, at `turn.complete`, and by the heartbeat.
2. **Lease.** `session.start` starts a 30 s `$.clock.every` heartbeat that renews (`touch`) every ticket the mod is using. The coordinator releases a ticket of a heartbeating client not renewed for 300 s. Rows written by older clients (no load ID) never expire, so mixed versions stay safe.
3. **Idle release.** A ticket with no busy work, no wait and no acquisition in progress for 120 s is released by the heartbeat: a turn whose end was never heard cannot keep its slot.
4. **Adoption.** Each module load has its own ID. On `session.start` it releases every ticket of the same owner held by another load (a hot reload or plugin update discards the previous load's state and timers).

## Subagents and the stall limit

Claude Code fails a subagent whose model step shows no progress for 600 s, and waiting in a `turn.step` hook is no progress. Three mechanisms keep subagents under that bound. `agent.spawn` records each subagent's parent. A parent yielding for `Agent`/`Task` parks its granted ticket instead of releasing it; the first `enter` of one of its subagents (or of the parent itself) claims it, and the heartbeat releases an unclaimed one after 60 s. Tickets carry a rank: 0 for subagents and later generations of a turn, 1 for a turn's first; `_promote` grants by rank, then sequence. A subagent's step still queued after 420 s (the stall clock runs from the step's start, so the model keeps 180 s for its first chunk) sends `force`, which grants it over the limit only in manual mode; automatic mode rejects the override; the pool stays over the limit until it drains, and `auto.log` records the overdraft.

A sprint (`/slots sprint [all] [M]`, op `sprint`) is the other overdraft, for urgent work. The `sprints` table holds a session ID (`*` for every session) and an end time, at most 60 minutes ahead; `minutes: 0` ends every sprint, and `reap` drops expired rows. While a session sprints, `_promote` grants its queued tickets regardless of the limit, unless the limit is 0 (a pause stops a sprint too), and `_rotate` leaves its granted tickets alone. Sprint tickets count as granted, so other sessions start nothing new until the pool drains under the limit; once the sprint ends its tickets rotate like any other.

## Automatic limit

The mod reports Claude Code's usage windows (`five_hour`, `seven_day`: percentage used, reset time) from `session.measure` and its heartbeat via `$.session.usage()`, only when they change. The coordinator keeps one row per window, the highest percentage for the same reset time (sessions read it from different responses), and drops readings of a window that already ended. A reading more than 5 points under the stored one for the same reset time is a restart of the account's window (a plan change): it replaces the row, clears that window's rate log, and the limit starts again from the normal limit. `reset` (from `/slots reset` or `guard.py reset`) clears the control table and, with `usage` (`/slots forget`, `guard.py forget`), every reading; each reading that changes a window is also appended to `readings.log`, never cleared; `configure` (`/slots agents|max|auto|quantum`, `guard.py configure`) rewrites the configuration and then resets the control table, so a change applies at once rather than one step per 600 s.

On every operation the coordinator computes a continuous ceiling for each valid window: `98 * (now - (reset - length)) / length`. No rounded daily quotas are used. `windows()` exposes `ceiling`, `margin`, `agents` (capacity), `rate` (points per agent-hour of work) and its `source` (`measured`, `inherited`, `default`), and for the week the learned `hours` a day. `capacity()` is `min(spread, within) / rate`: `spread = max(0, 97 - percent) / (share * seconds_left)`, where `share` is the learned duty (`duty()`, the active share of the last seven days blended with an 8-hour prior) for the week and 1 for the five-hour window; `within = max(0, ceiling + 1 - percent) / min(3600, seconds_left) + 98 / length`, what stays within the pause tolerance for the next hour. Rates and recorded loads over the same observation interval give the rate per agent (clock-time load includes idle time, just like clock-time burn). Recent weekly rates count active 5-minute buckets, with one working hour minimum and two maximum; five-hour rates use clock time, ten minutes minimum and one hour maximum. A flat or absent rate falls back to the per-agent rate the previous window of the same kind ended with (`_inherited`, when it ended within one window length; `usage_log` keeps two days), then to priors of 20 points/hour (five-hour window) and 1 point/hour (week). `activity` and `load` survive resets.

`auto_limit` floors the smallest supported concurrency, keeping at least one agent while within the ceiling. Reductions apply immediately, independent of `changed`; recovery adds one slot per 600 seconds only with 10% headroom for the resulting limit. After an hour idle, recovery settles without the cooldown. A live window more than one point above its continuous ceiling temporarily sets `effective=0` until the line is back within that point. At 98% it waits for reset. The stored reduced limit survives a line pause. Excess agents yield at their next `rotate`/model acquisition even before their quantum expires or without other waiters; running calls are not interrupted. Forced admission is rejected in automatic mode, including at positive limits. Explicit sprint commands remain concurrency overrides, but cannot bypass pauses. Capacity below one is visible: without throttling individual calls, a one-agent floor cannot promise that all workloads avoid a pause. All sessions must be restarted after updating to avoid older coordinators applying a different policy.


An evicted or expired ticket rejoins the back of FIFO once on the agent's next operation; a second refusal stops the turn. Under coordinator lock contention an acquirer keeps waiting rather than aborting the turn; other operations fail and are retried. Configuration initialization is atomic. Legacy configuration migrates only when every recorded legacy owner is confirmed dead, then replaces both limits with their minimum. Restarting participating sessions after an update is still recommended; a hot replacement releases the previous load's tickets.

`statusline.py` reads the one pool without modifying state. The optional wrapper preserves the previous statusline and appends the agent count. Detached tools and uninstrumented model paths remain outside this cooperative limiter; it is not a security boundary or token budget.
